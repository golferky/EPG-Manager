## Deploying a dashboard change (server.py)
1. Open a PR and merge it only when the user says so ("open the pull request", "merge it"; "open the pull request then merge it" means both). Before merging, merge `origin/main` into the branch. Squash merges leave version-line conflicts; keep the branch's newer `VERSION`.
2. Mac: `cd ~/EPG-Manager && git pull`
3. Mac: `scp ~/EPG-Manager/server.py ~/EPG-Manager/sd_guide.py ~/EPG-Manager/episode_match.py GaryAdmin@192.168.1.176:/share/CACHEDEV1_DATA/EPG-Manager/` (ALL THREE files: the dashboard calls sd_guide.py for every guide fetch; a change to it that is not copied does nothing)
4. QNAP: `cd /share/CACHEDEV1_DATA/EPG-Manager && ./start_epg_server.sh`, then `grep -m1 '^VERSION' server.py` to confirm the new version.
- Shortcut for steps 2 to 4, run on the Mac: `~/EPG-Manager/mac/deploy_dashboard.sh` (pulls, copies server.py and sd_guide.py, restarts the dashboard, then checks the RUNNING dashboard reports the new version; the version in the file alone proves nothing).
- A change to `recording_agent.py` only needs the Mac `git pull`, then `mac/safe_restart.sh --pull --timeout 14400` (leave the window open). From recorder v20261120b on, **recordings survive a recorder restart**: each recording's ffmpeg runs in its own session, a note about it (never the stream address) is kept in `<local_recordings>/.recorder_state`, and the restarted recorder takes over every recording it finds there (follows the running ffmpeg, then converts, checks, files and reports as usual). `safe_restart.sh` therefore restarts while recordings are running once the RUNNING recorder is v20261120b or later; it still waits for a recording that is being converted or filed, for one starting within about 150 s, and (for an older recorder) for any recording. The first restart onto v20261120b must wait for idle, because the old recorder stops its recordings when it is restarted. `mac/test_restart_survival.sh` proves with a throw-away launchd job that macOS lets a detached process outlive `launchctl kickstart -k`; if it fails, run it with `--abandon` and set `AbandonProcessGroup` in the recorder's launchd plist. An ffmpeg started by hand never holds a restart up.

## Naming 24/7 captures
- `mac/identify_episodes.py --show "Everybody Loves Raymond" --folder DIR [--apply]`: for episode videos with no guide data. It listens to each video (faster-whisper, installed once with `pip3 install faster-whisper`, runs on the Mac), matches the speech to the TMDb and OMDb plot summaries of every episode of the show (fetched through the dashboard), and prints the best match with the next closest. It is a GUESS: only a confident match (best clearly ahead of the runner-up) is filed in Plex, and only with `--apply`; unsure ones stay put, and `--accept "2026-11-22_0808=S02E15"` adds one you checked by eye. Transcripts are kept in `DIR/.transcripts` and reused. The owner wants Raymond in Plex only when an episode can be identified.

- From recorder v20261123i the speech match discounts words that the other transcripts (the batch plus the ones kept in the holding folder's `.transcripts`, `--background DIR` by hand) also contain (`spoken_weights`: weight 0.3 for a word in all of them, 1.0 for one in none), because sitcom plots made of "Ray", "Debra", "life" scored 1.00 against almost any episode: on Nov 23 it filed Fascinatin' Debra as Sex Talk and Anniversary as Be Nice. Plot-only matching stays a GUESS: confirm by watching and use `--clue`.

## Watching vs recording
- A recording always wins the streaming connection (dashboard v20261122i). Live Play (VLC playlist, the iOS `vlc://` address, and the browser player) goes through a RELAY in the dashboard (`/epg-web/api/play/proxy`), not straight to the provider, so the player never receives the provider address or login and the dashboard can end the viewing. The relay refuses to start, and ends itself, from two minutes (`PLAY_CUTOFF_SECONDS`) before a recording starts on the same connection, or while one is recording (`_viewing_blocked_by_recording`; Eaglecast one connection, PrimeStreams its panel `max_connections`). The player is told which recording and when. `play_relay: false` in the dashboard config goes back to handing out the provider address directly (then nothing can end a viewing). On a live airing, Play is judged as live viewing (`_airing_play_state`), not by the whole recording window.

## Episode guesses (shows whose guide listings have no season/episode, such as every ANTENNA TV classic)
- First choice, exact: descriptions come from one shared source, so if the SAME text is on a numbered airing of that show on another channel (FETV, DTV323 ...), that is the episode: score 100%, `source: guide`, no guessing (`_guide_known_episode`; `/api/guide-descriptions` reports it as `episode` and `mac/name_episodes.py` uses it first). Only when there is no exact text does it fall back to wording similarity, which is a GUESS.
- The programme window matches each unnumbered airing's description to the series' episodes and shows `≈ S2E16 · Name (87%)` (confident) or `maybe S2E16 ...` (30%+), and a confident match marks the show as a series so Record series appears. The wording guess is DISPLAY ONLY, never written into the guide, and an unnumbered recording of it is filed unnamed in `TV Needing Episode Info` until you name it. An EXACT match (`source: guide`) IS used when booking: `/api/record` and the series/Wanted pass fill in season, episode and title for an airing the guide did not number, so it is filed and named in Plex like any numbered recording, and the series pass can then skip episodes already in Plex. Only episode-level listings (`prog_type` EP) count as the numbered side, and a text found on two different episodes is ignored.
- Sources: TMDb (episode list, fetched in the background the first time a show's window opens, cached 24 h) plus OMDb plots (`/api/omdb-episodes`, fetched in the background into `omdb_episodes_cache.json`, at most 800 OMDb requests a day; the first window open for a show may need a second look 8 seconds later). The matching code is `episode_match.py`, shared with `mac/name_episodes.py` (`--source tmdb+omdb`, `--evaluate` to measure a source against episodes you already know). `episode_match.py` must be deployed with `server.py`.
